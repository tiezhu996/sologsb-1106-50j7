# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、留版版本、修版、套色印制批次与售出追溯串成一条链：

- 标刻成与每次返修都会留下不可变的**版片版本**（首版、第二版……）；
- 登记印制批次时**逐版固定本批版本快照**，日后返修只新增版本，不改旧批次；
- 售出按**作品编号**绑定印制批次，同一作品只保留一条有效售出，退货保留原关联并待复检；
- 返修前自动列出受影响的已售作品；追溯页可从作品展开到批次、版片版本与修版沿革；
- 旧档案缺少版本快照时按「旧档断点 / 旧档补建」兼容展示，不冒充当时真实留版。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 新增 `blockVersions`（版片版本）与 `sales`（售出登记）两张表，并为旧数据做兼容迁移：
  - 旧版片按当前状态与刻版/修版节点补建一条 `legacy` 版本；
  - 旧批次按同画稿已成版片回填 `legacy` 版本快照，未刻成版片留空（断点）；
  - 所有记录回填 `schemaRev: 3`。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入画稿、版片、刻工、留版版本、印制批次（含版本快照）、工序节点与售出记录。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

### 追溯链与版本规则

```text
作品（pieceNo）──1:1 有效售出──> 印制批次 ──快照──> 版片版本（刻成/修版，不可变）
                                  │                                      │
                                  └─ 旧档无快照：断点展示                 └─ 修版工序节点
返修 ──新增版本（旧批次快照不变）──> 自动列出固定旧版的已售作品（含退货待复检）
```

- 批次 `blockSnapshots` 在批次登记时写入，之后永不修改；
- 退货只改变售出状态（`有效 → 已退货待复检`），不解除与批次的绑定；
- 旧数据记录可能没有 `blockSnapshots` 或带 `legacy: true`，前端按断点样式展示。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号、标刻成留首版、返修留新版并列出受影响已售作品 |
| `/blocks/:id/nodes` | 工序节点时间线 | 推进或回退工序节点，登记操作人、时间与耗时 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，逐版填写套色偏差，并固定本批版片版本快照 |
| `/sales` | 售出登记与追溯 | 按作品编号绑定批次、同一编号唯一有效售出、退货待复检，展开作品→批次→版本→修版追溯链 |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
